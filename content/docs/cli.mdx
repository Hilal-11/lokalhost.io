## Installing lokalhost.io with the shadcn CLI

lokalhost.io components are distributed as a [shadcn](https://ui.shadcn.com) registry — no separate CLI to install, no separate tool to learn. If you already have a Next.js + Tailwind project, you can start pulling components in right away.

## Initialization

Use the `init` command to set up `components.json`, install core dependencies, and configure Tailwind + CSS variables for a new project.

<Tabs items={['npm', 'pnpm', 'yarn', 'bun']}>
  <Tab value="npm">
    ```bash
    npx shadcn@latest init
    ```
  </Tab>
  <Tab value="pnpm">
    ```bash
    pnpm dlx shadcn@latest init
    ```
  </Tab>
  <Tab value="yarn">
    ```bash
    yarn dlx shadcn@latest init
    ```
  </Tab>
  <Tab value="bun">
    ```bash
    bunx --bun shadcn@latest init
    ```
  </Tab>
</Tabs>

You'll be asked a few questions to configure `components.json`:

```txt
Which style would you like to use? › New York
Which color would you like to use as base color? › Zinc
Do you want to use CSS variables for colors? › no / yes
```

<Callout title="Already have shadcn set up?">
  If your project already has a `components.json`, skip `init` entirely — go straight to `add` below.
</Callout>

### Options

```txt
Usage: shadcn init [options] [components...]

initialize your project and install dependencies

Arguments:
  components          the components to add or a url to the component.

Options:
  -d, --defaults      use default values i.e new-york, zinc and css variables. (default: false)
  -f, --force         force overwrite of existing components.json. (default: false)
  -y, --yes           skip confirmation prompt. (default: false)
  -c, --cwd <cwd>     the working directory. defaults to the current directory.
  -h, --help          display help for command
```

  </Tab>
  <Tab value="pnpm">
    ```bash
    pnpm dlx shadcn@latest add [component]
    ```
  </Tab>
  <Tab value="yarn">
    ```bash
    yarn dlx shadcn@latest add [component]
    ```
  </Tab>
  <Tab value="bun">
    ```bash
    bunx --bun shadcn@latest add [component]
    ```
  </Tab>
</Tabs>

### Options

```txt
Usage: shadcn add [options] [components...]

add a component to your project

Arguments:
  components          the components to add or a url to the component.

Options:
  -y, --yes           skip confirmation prompt. (default: false)
  -o, --overwrite     overwrite existing files. (default: false)
  -c, --cwd <cwd>     the working directory. defaults to the current directory.
  -p, --path <path>   the path to add the component to.
  -h, --help          display help for command
```

## Namespaced registries (shadcn CLI 3.0)

Once `@lokalhost` is configured, you can use a shorter form instead of the full URL every time.

### Edit `components.json`

Add lokalhost.io as a registry:

```json title="components.json"
{
  "registries": {
    "@lokalhost": "https://lokalhost.io/r/{name}.json"
  }
}
```

### Then install with the shorthand

<Tabs items={['npm', 'pnpm', 'yarn', 'bun']}>
  <Tab value="npm">
    ```bash
    npx shadcn@latest add @lokalhost/[component]
    ```
  </Tab>
  <Tab value="pnpm">
    ```bash
    pnpm dlx shadcn@latest add @lokalhost/[component]
    ```
  </Tab>
  <Tab value="yarn">
    ```bash
    yarn dlx shadcn@latest add @lokalhost/[component]
    ```
  </Tab>
  <Tab value="bun">
    ```bash
    bunx --bun shadcn@latest add @lokalhost/[component]
    ```
  </Tab>
</Tabs>

Example:

<Tabs items={['npm', 'pnpm', 'yarn', 'bun']}>
  <Tab value="npm">
    ```bash
    npx shadcn@latest add @lokalhost/download-button
    ```
  </Tab>
  <Tab value="pnpm">
    ```bash
    pnpm dlx shadcn@latest add @lokalhost/download-button
    ```
  </Tab>
  <Tab value="yarn">
    ```bash
    yarn dlx shadcn@latest add @lokalhost/download-button
    ```
  </Tab>
  <Tab value="bun">
    ```bash
    bunx --bun shadcn@latest add @lokalhost/download-button
    ```
  </Tab>
</Tabs>

<Callout type="warn" title="This shorthand only works once configured">
  `@lokalhost/[component]` only resolves for projects that have added the `registries` entry above to their own `components.json`. If you haven't configured it yet, use the direct URL form instead — it works with zero setup.
</Callout>
